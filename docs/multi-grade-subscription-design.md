# 3級種統合・全級共通サブスクリプションの設計方針

作成日：2026年11月6日。当初の設計記録。後続依頼により月額500円（税込）・各級模試1〜3無料／4以降有料が確定し、[実装](multi-grade-subscription-implementation.md)へ進んだ。以下の未実装・未決は当初時点の記録であり、現在の範囲は実装記録を優先する。

世界遺産ラボを1級・準1級・2級に対応させ、3級種共通のサブスクリプションで提供するための方針を記録する。「全級」は本書ではこの3級種を指し、3級・4級・マイスターや他の資格サービスを含めない。

## 確定した方針と今回の範囲

2026年11月6日のユーザー依頼により、次を確定した。

- 一つのアプリ・アカウントで1級・準1級・2級を演習できるようにする。
- 級を切り替えて学習し、問題・模試・進捗・正答率・履歴・お気に入り・復習対象を級別に扱う。
- 一つのサブスクリプションで、3級種の公開済み有料範囲を利用できるようにする。級の変更による追加契約・追加請求は行わない。
- サブスクリプション化の対象は**この世界遺産ラボだけ**とする。派生元テンプレートや日本史・世界史・美術等の別サービスには適用しない。
- 既存2級の問題ID・選択肢ID・回答履歴・お気に入り・リンクを保持して移行する。
- 今回はドキュメントを作成する。実装・作問・DB登録・販売開始は行わない。

以下の「設計案」は実装時の判断材料であり、料金等の「未決事項」は別途決定する。本書は実装、DB変更、Stripe設定、コミット・push、デプロイの依頼を兼ねない。

## 現状と変更点

コード・設定を2026年11月6日に確認した現状と、将来の変更対象を分ける。実際のStripe契約・顧客や稼働DBの利用者情報は今回確認していない。

| 項目 | 現在 | 将来の方針 |
| --- | --- | --- |
| 対象級 | 2級のみ。単一の共通設定 | 1級・準1級・2級の設定と学習データを級別に管理 |
| 問題の識別 | 模試番号＋問番号。級の項目なし | 級＋模試番号＋問番号を区別し、既存IDを保持 |
| 認証 | Better Authによる一つのアカウント | 同じ認証基盤を継続。級ごとの再登録は不要 |
| 課金処理 | Stripeの一回払い。購入に基づく会員資格 | 定期請求・支払済み期間に基づく全級共通の利用資格 |
| 会員資格 | 購入由来の資格は`active/revoked`で管理し期限がない。検証用アクセスは別に期限を持つ | 契約状態と利用可能期間を区別し、期限をAPIで判定 |
| 販売 | リポジトリ上の案内では販売無効 | 商用条件・実装・検証後、別途依頼で開始 |

現行の500円という一回払い設定と「模試1〜5が無料」という枠組みは、サブスクリプションの価格・無料範囲として合意した値ではない。既存の案内や処理を現在のサブスク機能として紹介しない。

現行実装の入口：[試験設定](../config/exam.json)、[共有設定スキーマ](../frontend/shared/schemas/exam.ts)、[DBモデル](../frontend/prisma/schema.prisma)、[購入処理](../frontend/server/services/payment-checkout.ts)、[会員資格判定](../frontend/server/core/auth.ts)。

## 級ごとの試験設定

公式の[受検の目安](https://www.sekaken.jp/each_grade/criterion/)を2026年11月6日に確認した。演習の級設定は、次の違いを表現できるようにする。

| 級 | 出題範囲の目安 | 本試験の問題数・時間 | 満点 |
| --- | --- | --- | --- |
| 2級 | 日本の全遺産＋世界の遺産300件 | 60問・60分 | 100点 |
| 準1級 | 日本の全遺産＋世界の遺産700件 | 60問・60分 | 100点 |
| 1級 | 世界遺産全件 | 90問・90分 | 200点 |

問題数、選択肢仕様、模試枠数、分類・配点比率、教材の版、時事の基準日は級ごとの設定として持つ設計案とする。2級の60問や分類比率を全級へ流用しない。時間・配点を設定に記録することと、制限時間付き受験・試験全体の配点採点を実装することは別であり、これらの機能追加は別途範囲を定める。

大分類の共通名は「基礎知識」「日本の遺産」「世界の自然遺産」「世界の文化遺産」「その他」を基本とする。級別の分類比率・公開判定を管理できるようにし、「その他」には前年・当年の世界遺産委員会等の時事を含める。出題順は分野を混在させた教材として固定し、原稿・DB・画面で問番号を一致させる。

新しい級の教材は、その級の公式テキスト・出題範囲・過去問分析を踏まえて別途作成する。同じ遺産を扱う場合も、2級の問題をそのまま1級や準1級の問題として複製・公開しない。

## 学習画面とUXの設計案

- ヘッダー等に現在の級と切替入口を常時表示する。模試一覧・問題メニューは選択中の級に絞り、未収録の級には準備状況を表示する。
- 初回は級を選び、次回は最後に使った級へ戻る。級を指定したリンクを開いた場合は、そのリンクの級を優先する。保存先はアカウントと端末の使い分けを実装時に決める。
- 学習位置は級別に保持する。切替時は別の級の回答途中データを引き継がず、未送信の入力を失う場合にだけ確認を表示する。
- 級別の正答率・模試進捗・履歴・お気に入り・間違えた問題の復習を表示する。難度や問題数が違う級の正答率は合算しない。全級の集計を設けるなら学習日数など共通に意味のある指標に限る。
- 復習の1周の対象は級ごとに固定し、次の周回で最新状態を取得する。級・ログイン・利用資格の変更時には、進行中の対象と古い応答を破棄する。
- 契約状況・支払方法・解約の入口は全級共通とする。購入前に対象の3級種、公開済み範囲、料金、請求周期、自動更新、利用期限を示す。
- サブスク解約とアカウント削除を別の操作として説明する。利用期限終了後もアカウント・学習記録を保持する案とし、保存期間と有料教材の履歴表示範囲は未決事項として決める。

利点は、昇級しても登録・課金をやり直さずに済み、基礎への戻り学習もしやすいこと。注意点は、級の取り違え、メニューの増加、一つの級だけ使う人の料金への納得感である。現在の級を明示し、普段の画面をその級に絞り、購入画面で利用範囲を具体的に説明する。

## データ・API・URLの設計案

論理構造は「級 → 模試 → 問題」とする。物理的なテーブル名・列名・設定JSONの構造は実装前に確定する。

| 対象 | 設計上の扱い |
| --- | --- |
| 問題・模試 | 級＋模試番号＋問番号の一意性を保証。同じ模試1・問1を別級にも持てる |
| 分類・公開件数 | 級ごとの設定・教材と対応。90問の級を60問の完成条件で公開しない |
| 履歴・お気に入り | 既存の問題ID・選択肢IDへの参照を保持し、問題から級を特定 |
| 復習・達成状況 | 級を指定して抽出・集計。級をまたぐ直積や誤った合算を防止 |
| 管理画面・取込 | 級の指定を必須にし、級別の検証・公開判定を行う。教材JSONの互換方式も定義 |
| 利用資格 | 一つの全級共通資格。級選択によって契約を切り替えない |

級は画面だけの絞り込みにせず、問題一覧・取得・回答・履歴・お気に入り・復習・管理・取込の各APIで検証する。ID指定の操作でも問題の実際の級と指定級の整合を確認し、管理者権限と有料範囲の利用資格はAPIがDBの現在値で判定する。

URL案は `/grades/2/practice/1/1`、`/grades/pre1/practice/1/1`、`/grades/1/practice/1/1` とする。識別子・パス名は未確定。旧 `/practice/1/1` は2級の同じ問題へ到達できる互換導線を残し、必要なクエリも維持する。

級をURL・APIパラメーター・キャッシュキーに含める。切替後に届いた前の級の応答を採用しない。ユーザーの切替操作でサーバーのグローバル設定を書き換えず、リクエストごとに級の設定を解決する。教材の共通形式は引き続き共有Zodスキーマを正本とする。

## サブスクリプションの設計案

### 契約と利用資格

既存のStripe接続を踏まえ、Stripe Billing、サブスクリプション用Checkout、契約管理用Customer Portalの利用を第一案とする。Stripeの定期請求は請求書・支払い・契約状態が非同期に変化するため、購入時だけでなく更新後の状態も扱う必要がある。[Subscriptions概要](https://docs.stripe.com/billing/subscriptions/overview)、[Webhookによる管理](https://docs.stripe.com/billing/subscriptions/webhooks)を参照（2026年11月6日確認）。

- 一人につき本サービスの契約を一つにまとめる。契約中・更新支払待ち等では既存契約の管理・支払再開へ案内し、重複契約を作らない。級別のPriceや購入ボタンは設けない。
- サブスクリプション用の継続課金Priceを使い、通貨・金額・周期・環境・本サービスとの対応を検証する。現在の一回払いPriceを転用しない。利用するSDK/API版と対応する支払方法は実装時に公式資料で確認する。
- 顧客ID、契約ID、請求書ID、処理済みイベントID、支払済みの対象期間、利用期限を保持する。既存の一回払いの購入・返金記録とは区別し、請求書ID等に重複防止制約を設ける。実際のモデル・制約は別途設計する。
- Stripe上の契約状態と、教材を利用できる資格を分ける。DBに記録した確認済みの対象期間と運用方針から資格を算出し、各APIで期限を確認する。期限切れWebhookの到着待ちで利用が無期限に延びないようにする。
- 購入完了の戻り画面やクライアントのフラグだけでは資格を付与しない。初回請求が未完了なら付与せず、支払確認から期間を反映する。無料トライアルは採用未決のため、現段階では権利付与を前提にしない。

Customer Portalは支払方法や契約の管理に利用できるが、提供する解約・プラン変更等の機能は商用条件に合わせて設定する。[Stripe Customer Portal](https://docs.stripe.com/customer-management)（2026年11月6日確認）。今回はProduct・Price・Portal・Webhook等を作成・変更しない。

### 状態と画面表示の案

以下は**推奨する設計案**であり、解約日・猶予・返金の商用条件を確定したものではない。

| 状態 | 有料範囲の扱い・画面案 |
| --- | --- |
| 未契約 | 別途決める無料範囲を利用。全級共通プランを案内 |
| 初回支払い未完了 | 新規の有料資格は付与せず、支払い状況を確認する入口を表示 |
| 支払確認済み・期間内 | 3級種の公開済み有料範囲を利用。次回請求日・利用期限を区別して表示 |
| 更新成功 | 確認した次の対象期間へ更新。同じ請求を重複処理して期間を二重加算しない |
| 期間末解約の予約 | 支払済み期間末まで利用し、以後の更新を停止する方式を推奨。終了日を表示 |
| 更新の支払失敗 | 支払済みの残存期間は維持。期限後の猶予の有無は未決。支払方法の確認を案内 |
| 利用期限終了 | 有料範囲のAPI利用を停止。無料範囲と再契約の入口を表示 |
| 即時解約・返金・紛争 | 利用資格の変更時点と返金対象期間を別途決定。一回払い時の失効処理を流用しない |

「契約がactiveなら常に利用可」「past_dueなら直ちに全期間を取り消す」といった単一状態だけの判定を避け、確認済みの期間と決定した例外方針を使う。契約が終了しても、期間末解約による支払済み期間の利用可否は別に判定する。

### 更新・解約・障害への対応

署名検証したWebhookを正本へ反映する。候補は `invoice.paid`、`invoice.payment_failed`、`customer.subscription.updated`、`customer.subscription.deleted` とCheckout関連イベント。採用イベント・ペイロード・支払期間の取得元は実装時のAPI版に合わせて確定する。[Stripeのイベント別の説明](https://docs.stripe.com/billing/subscriptions/webhooks)。

- イベントIDと請求書IDで再送・二重処理を防ぎ、利用期間は対象期間を反映して更新する。受信するたびに「1か月を足す」方式にしない。
- 到着順を信用せず、必要に応じてStripe上の最新状態と照合する。古いイベントで新しい支払済み期間を巻き戻したり、終了した資格を復活させたりしない。
- Webhookの失敗・再送・取りこぼしを検出し、再処理と契約状態の照合で回復できるようにする。資格不明時に有料アクセスを無条件に許可しない。
- 解約予約・再開・支払方法変更は同じ契約へ反映する。二重送信・同時操作でも重複契約を作らない。
- **アカウント削除の前に今後の請求停止を確認する処理が必要**。現在の退会処理は定期請求停止に対応していない。停止を確認できなければ契約との対応を先に消さず、再試行・問い合わせへつなぐ。解約方式と保存期間は未決事項に従う。
- 本文・個人情報・カード情報・Stripeイベント本文をログや引き継ぎへ記録しない。

## 既存データの移行方針

実装依頼を受けた後、対象環境・バックアップ・既存資格を確認し、追加型のマイグレーションで既存問題を2級へひも付ける。適用済みマイグレーションやbaselineを書き換えず、DBの初期化・教材の再投入・IDの採番し直しを行わない。

問題本文を変更しない級情報の補完で履歴を失効させない。現行の[教材書込処理](../frontend/server/services/learning-writer.ts)には教材変更時の履歴処理があるため、移行を通常の問題編集として扱わない。級追加後も、既存のログイン・2級の履歴・お気に入り・旧URLが継続利用できることを確認する。

過去の一回払い会員が存在する場合の扱いは未決。販売停止の案内だけから「既存購入者はいない」と断定しない。既存の利用権を黙って期限付きに変更したり、既存アカウントへ自動で定期契約・請求を発生させたりしない。購入記録は保持し、旧資格と新契約の優先関係を決めてから移行する。

| 無料範囲 | 各級の体験問題数・模試数・利用できる機能を決める。現行5回を自動適用しない |
| 無料トライアル | 有無・期間・支払方法登録・終了後の扱いを未決とする |

| 支払失敗 | 猶予の有無・期間、再試行中の資格、回復時の扱いを決める |
| 返金・紛争 | 対象期間、利用資格の変更、日割りの有無を決める |
| 既存の一回払い資格 | 継続・優遇・移行の方式と案内を、既存条件を確認して決める |

| 提供開始 | 級ごとの教材数・公開順・準備中の案内・発売時期を決める |
| 販売表示 | 規約・特定商取引法表示・問い合わせ先・更新案内を提供条件に合わせて整える |

## 実装依頼後の進め方と受入条件

将来の手順案は、①商用条件の決定、②級別の設定・データ移行・画面、③サブスク処理とテスト環境での確認、④依頼された級の作問・登録と画面確認、⑤販売条件・公開範囲の確認、の順とする。販売開始や本番反映は別途明示依頼を受ける。空の模試枠を埋めるための仮問題は作成しない。

以下は**将来の実装の受入条件**であり、今回実施済みの検証ではない。

- 同じ模試番号・問番号を級別に登録でき、2級・準1級の60問と1級の90問の検証が混ざらない。
- 一覧・回答・履歴・お気に入り・復習・管理・取込・公開判定で級が混ざらず、直接API操作でも権限を検査する。
- 既存2級のID・履歴・お気に入り・ログイン・旧URLを維持する。級の補完だけでは履歴を消さない。
- PC・スマートフォンで級が明確に分かり、切替・戻る操作・直接リンク・遅延応答でも別級の情報を表示しない。
- 一つの契約で3級種の公開済み有料範囲を利用でき、級変更で請求や契約が増えない。
- 初回未払い、更新成功・失敗・回復、解約予約・再開・期間終了、重複契約、返金等を決定した方針どおりに処理する。
- Webhookの再送・順序逆転・遅延・再処理で資格が過剰延長・誤失効せず、期限終了後は全対象APIが有料アクセスを拒否する。
- 退会時に今後の請求停止を確認し、停止失敗時も契約を追跡・回復できる。
- 旧一回払い資格とサブスク資格を区別し、無期限の旧判定が新しい期限検査をすり抜けない。
- 独立したテスト環境・合成データ・Stripeのテスト環境で確認し、他サービスの設定・契約を変更しない。
